# Резервное копирование и восстановление

Ежедневная копия хранится в `/opt/paperclip/backups` семь дней, с правами
root-only. Эта версия daily backup предназначена для LAN-сервера с UID
worker/publisher/memory `21001/21002/21003`; при других UID она останавливается
до изменения служб. На старом VPS её не разворачивать: там UID публикатора 999
совпадает с UID PostgreSQL в контейнере. Копия на этой же ВМ не защищает от полной потери сервера.

`swarm/scripts/backup.sh` сохраняет полный набор для реконструкции:

- `database.dump`, `database.roles.sql`, `database.rows.sha256`: PostgreSQL,
  роли (включая секретные hashes паролей) и отпечаток строк таблиц;
- `files.tar.gz`: конфигурация, секреты, скрипты, файлы Paperclip и Caddy state;
  существующий `compose.override.yaml` включается обязательно;
- `worker.tar.gz`: целиком `/opt/loginom-worker`, `/opt/loginom-swarm`
  (включая toolchains, CLI, node_modules, recovery, Git и профили),
  `/etc/loginom-swarm`, память, профиль публикатора, связанные units/AppArmor;
- `secrets.tar.gz`: сведения о системных аккаунтах, существующие
  `/etc/loginom-swarm-vpn`, `/etc/ssh`, `/root/.ssh` и служебные root-конфигурации; также VPN binary/helpers
  `/usr/local/libexec/swarm-vpn`, сетевой drop-in
  `/etc/systemd/network/10-netplan-ens18.network.d` и Docker drop-ins
  `/etc/systemd/system/docker.service.d`;
- `images.json`, `packages.tsv`: версии и образы; `active-*.txt`: прежнее состояние
  служб; `SHA256SUMS`: целостность всего набора.

Все tar-архивы сохраняют ACL, extended attributes и числовых владельцев
(`--acls --xattrs --xattrs-include='*' --numeric-owner`). При восстановлении
на Linux использовать соответствующие tar flags и root; восстановление владельцев
на другой сервер выполнять по manifest, учитывая согласованное сопоставление UID.

Все файлы копии имеют права `0600`, каталог — `0700`. Секретный архив нельзя
публиковать или распаковывать в общедоступный каталог. Список системных аккаунтов
служит для точного сопоставления UID, а не для замены `/etc/passwd` на новом хосте.
Архивы не включают каталог самих резервных копий. Кэш не исключается ценой
потери установленного runtime; исключён только активный файл `state/heavy.lock`.

Скрипт берёт отдельный backup lock и общий heavy-stage lock. Занятый backup lock
возвращает exit 75; тяжёлый этап ожидается до восьми часов, затем также exit 75.
Возраст блокировки не является основанием удалить её.

До первой остановки скрипт успешно считывает состояния всех служб и контейнеров.
Ошибка определения состояния прерывает копирование. Paperclip, Caddy и активные
worker/memory/publisher units останавливаются **до любого снимка файлов**.
Оставшиеся процессы служебных пользователей блокируют снимок. PostgreSQL остаётся
запущенным внутри Compose для логического dump. Прежние stopped/failed службы
не запускаются; trap возвращает только ранее активные службы, включая ошибку dump.

Сначала создаются несжатые неизменяемые архивы. После возврата прежнего состояния
служб они сжимаются, проверяются hashes и получают окончательное имя. Ошибки
снимка, восстановления служб или сжатия оставляют `.partial-*`; сообщение о
готовности не печатается. Удаление по retention выполняется только после успешной
публикации новой копии. Этот ежедневный скрипт **не заменяет** миграционный cold
collector без рестарта, который применяется для окончательного freeze источника.

Порядок проверки на сервере:

```sh
/opt/paperclip/scripts/backup.sh
/opt/paperclip/scripts/verify-backup.sh /opt/paperclip/backups/TIMESTAMP
```

Проверка создаёт отдельную временную БД, восстанавливает dump с exit-on-error и
сравнивает fingerprint содержимого всех таблиц с моментом снимка. Сравнивать с
уже перезапущенной live-БД неправильно: её audit/heartbeat записи изменяются.
Архив исполнителей распаковывается в приватный временный каталог; проверяются
регистрации, профили и права auth.json. Затем удаляются только созданные этой
проверкой временная база и временный каталог.

25.09.2026 проверен снимок `20260925T002721Z`: SHA256 трёх архивов и fingerprint,
210 таблиц, точное совпадение строк с исходным снимком, конфигурации приложения,
профилей и регистрации исполнителей. После рестарта повторно прошли sandbox
probes; Paperclip `/api/health` вернул `ok`. Первую копию `20260925T002430Z`
сохраняем: её restore прошёл, но старое сравнение с live-БД закономерно не совпало.

Для аварийного восстановления сначала остановить запись и сохранить текущие
данные отдельным снимком. Развернуть копию в новом каталоге/новых volumes,
восстановить БД и файлы с исходными UID/правами, установить pinned runtime,
загрузить AppArmor и systemd, проверить health и изоляцию, затем переключить
рабочую конфигурацию. Не распаковывать архив поверх работающей production-системы.
Не использовать `down -v`. После миграций БД откат одного образа не считается
безопасным: восстанавливать согласованный снимок приложения и БД.

Чистая полная реконструкция VPS и восстановление source-built образа форка ещё
не проверены; текущий PASS относится к отдельной БД и извлечённым файлам.

## Личный GitHub OAuth публикатора

С 25.09.2026 worker archive включает `/var/lib/loginom-swarm-publisher`.
Это секретный профиль отдельного системного пользователя; архив остаётся root-only.
После переноса на новый VPS выполнить `install-publisher.sh`, восстановить профиль,
исправить владельца на созданный loginom-publisher и проверить 0700/0600.
`verify-backup.sh` сравнивает восстановленные файлы с `snapshot-manifest.json`,
не с текущими OAuth/config на сервере: авторизации могут изменяться после снимка.
Manifest создаёт `backup-manifest.py` из неизменяемых plain tar уже после рестарта
служб; значения секретов в JSON не включаются. После отдельного извлечения
проверяются hashes, type/mode/uid/gid, symlinks, сохранённые ACL и xattrs.
Для Linux-проверки нужны GNU tar, Python с xattr API и `getfacl` (пакет `acl`).
Helper должен быть установлен в `/opt/paperclip/scripts/backup-manifest.py`.
Старая копия без manifest не получает полный PASS файловой проверки: verifier
явно завершается ошибкой после отдельной проверки БД.
`verify-publisher.py` отдельно проверяет актуальность OAuth и права.
Если GitHub отозвал токен, требуется новый device-вход; восстановление файла
само по себе не восстанавливает отозванные права. Подробности в GITHUB-PUBLICATION.md.

## Проверки изменения ежедневного backup

`python3 -m unittest discover -s swarm/tests -p 'test_backup*.py' -v` исполняет
скрипт с изолированными командами-заглушками: остановленный Paperclip не
запускается, активный запускается обратно, ошибка определения состояния не
меняет службы, ошибка dump не публикует готовую копию, а архивы покрывают полный
runtime и создаются после остановки writers. Это проверка логики; реальный dump
и восстановление требуют отдельной серверной проверки.

Manifest-тесты дополнительно проверяют отсутствие значений credential в JSON,
отказ при изменении содержимого/прав и запрет небезопасных архивных путей.
Проверка xattr на Mac пропускается, если Python не предоставляет `os.getxattr`;
перед серверным PASS требуется Linux-проверка реальных ACL/xattrs. Архивный
manifest защищает от случайных изменений и дрейфа live-профилей, но не заменяет
доверенное хранение SHA256SUMS при угрозе подмены самого backup.
