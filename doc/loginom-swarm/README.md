# Loginom Swarm

Loginom Swarm сохраняет Paperclip как систему задач, pipelines/cases, секретов,
прав и аудита. Каталог `swarm/` содержит серверные интеграции и эксплуатационные
инструменты. Реализации узлов остаются в `gooddaytoday/loginom-ai-agent`, ветка
`loginom`.

**Статус: идёт подготовка. Обработку Sampling пока запускать нельзя.**
Актуальное состояние и незавершённые проверки: [CHECKPOINT.md](CHECKPOINT.md).

## Архитектура

Ручной старт одного case → допуск → подготовка → разработчик Astra medium →
независимый ревьювер Astra medium → полная сборка CLI → standalone CLI Sol low →
проверка результатов координатором → ветка и PR → ожидание пользователя.

Координатор работает служебным кодом в контейнере Paperclip.
Исполнители работают отдельной непривилегированной службой на том же VPS.
Это согласованное 25.09.2026 изменение после проверки вложенного sandbox в Docker.
Он использует штатные leases, expectedVersion, requestKey и историю Paperclip.
Отдельной очереди/базы кампаний нет. Проверки политики находятся в
`swarm/runtime/evidence.py`; они сами не запускают модели и не выдают допуск.
Разработчик и ревьювер не получают секреты Paperclip или ключ публикации.
Публикация использует штатную GitHub OAuth identity инициатора через Paperclip.

Каждая роль получает самостоятельный Git checkout и постоянный профиль.
Ревьювер читает зафиксированный commit; координатор проверяет неизменность дерева.
Приёмщик получает только бизнес-ТЗ и входные данные. Эталон и история разработки
остаются снаружи его окружения. Два цикла исправлений, 30 минут приёмки, 8 часов
активной обработки. Неизвестный результат мутации означает остановку и разбор.

## Память

Серверная генерация памяти отдельна от локальной 20260924.1. Целевой Peer:
`viking://user/kartamyshev/peers/-Users-kartamyshev-Git-loginom-ai-agent/memories`.
Оператор регистрирует точные checkout. Серверный путь не становится новым Peer.
Настоящие Codex thread ID, SessionStart и capture cursors остаются раздельными.
Мастер-ключ памяти не попадает в окружение моделей. Приёмщик не получает память
разработки. До проверки capture/extraction и обратного чтения допуск закрыт.

## Исходная версия и изменения

`swarm/upstream.lock.json` фиксирует проверяемую исходную версию.
`swarm/upstream-changes.json` содержит реестр изменений оригинальных файлов.
Проверка: `python3 swarm/scripts/check-upstream.py`.
Собственные компоненты: API/SSH — `swarm/scripts`; развёртывание — `swarm/deploy`;
политики исполнения — `swarm/runtime`; память — `swarm/memory`; тесты — `swarm/tests`.

Старая инфраструктура импортирована как baseline. Файлы `BASELINE-*` и
`swarm/config/{pilot.json,PILOT.md,AGENT.md,CHECKPOINT.md}` описывают прежний SSH
пилот, а не готовый Swarm. Старые исходники `/Users/kartamyshev/Git/paperclip`
сохранены. Производственные ID и данные не пересоздавать.
