# Перенос Loginom Swarm в локальную сеть — согласованный план

## Результат и границы

Перенести сервис с `82.22.23.10` на `10.200.4.106`, сохранив данные,
учётные записи, серверные авторизации, рабочие каталоги и незавершённые операции.
Основной адрес — **http://loginom-swarm.bg.local**, порт **80**, только локальная
сеть. Модели подключаются к провайдерам через VPN с выходным IP `185.21.15.251`.

Назначение: Ubuntu 26.04, 16 vCPU, около 32 ГБ RAM. Гостевая ОС видит диск
200 ГиБ, но раздел `/dev/sda2` и ext4 перед переносом требуется расширить с 80 ГиБ.
Пользователь разрешил удалить существующую установку и данные назначения;
ОС, SSH и сетевой доступ сохраняются. Источник остаётся замороженным минимум
семь дней после переключения и автоматически не удаляется.

Сохранить стабильный Paperclip `v2026.916.1`, commit
`d554c4789ed3930f8a53ac9fdf6503b3187097da`, и фактические digest образов.
Исполнители и шлюз памяти остаются службами хоста; приложение и БД — в Docker.
Не совмещать перенос с обновлением Paperclip, исправлением CLI, завершением
координатора или развёртыванием нового образа форка. **Sampling не запускать.**
Сохранить блокировку CLI 0.1.16 и шесть recovery-записей; готовность миграции
не означает готовность автономной обработки.

## Координация, репозиторий и доступы

- Разработка — в `kartamyshev-dev/loginom-swarm`, отдельная ветка и PR в `swarm`,
  без автоматического слияния. Сохранить текущую историю, включая
  `ca32e9d2c615f13d2e27d72bb2b2455a589bca15`, и ранее подготовленный PR №1.
- Субагенты разрешены для независимых проверок, подготовки скриптов и документации,
  если это ускоряет работу. Основной агент проверяет результаты; изменения общих
  серверных настроек, остановка источника, окончательный снимок и переключение
  выполняются последовательно. Конкурирующие изменения запрещены.
- Секреты хранить только в исключённых из Git `.env`/`private`, с правами `0600`.
  Не передавать их в журналы, документы, образы или окружение моделей.
- Перед очисткой проверить IP, SSH host key и machine ID назначения. Перечень
  удаления должен быть явным; очистка источника запрещена.
- Сверить фактический runtime с Git. Сохранить защищённый manifest версий,
  контрольных сумм, владельцев, прав и идентификаторов объектов. В отчёте — только
  безопасная сводка. Незавершённые изменения других задач не переписывать.
- Linux-компоненты `deploy-vpn` ещё не полностью представлены в его Git-истории.
  Использовать проверенную копию с hashes и происхождением; не коммитить чужие
  незавершённые изменения автоматически.

## Подготовка назначения и DNS

1. Повторно проверить identity, диски, службы, контейнеры, mounts, версии пакетов,
   владельцев, runtime hashes, paused cases и recovery-состояние обоих серверов.
2. Остановить старый Compose назначения и удалить только его контейнеры, тома,
   каталог и ненужные образы по проверенному перечню. Базы не объединять.
3. Сохранить описание разметки. Проверить `growpart -N /dev/sda 2`, затем выполнить
   `growpart /dev/sda 2` и `resize2fs /dev/sda2`. Подтвердить размер через `lsblk`
   и `df`. При другой разметке остановиться; не форматировать раздел.
4. Сохранить установленный Docker/Compose и зафиксировать версии. Не выполнять
   необязательное обновление системного стека одновременно с переносом.
5. Установить hostname `loginom-swarm`, сохранив MAC и DHCP client ID. Передавать
   имя через DHCP, сохранить домен `bg.local`. Обновить аренду контролируемо.
6. Проверить автоматическую регистрацию `loginom-swarm.bg.local` через внутренний
   DNS `10.200.0.3`; настроить направление зоны `bg.local` к внутренним DNS.
   Проверить имя с сервера и Mac, включая Mac с VPN, после DHCP renew и reboot.
   При необходимости добавить точечные правила LAN/DNS в клиент VPN.
7. Не заменять корпоративную регистрацию записью только в `/etc/hosts`.
   Если регистрация не появилась, остановить переключение до исправления DNS.
   Основной URL использует имя, а не изменяемый DHCP-адрес.

## VPN и запрет прямого выхода

Использовать sing-box **1.12.25**, официальный архив и проверенный SHA256.
В ходе выполнения пользователь заменил исходный VLESS URI секретной подпиской.
Принятое подключение — **Trojan поверх WebSocket и TLS**, endpoint
`185.21.15.251:443`, SNI `ams-net.duckdns.org`. Проверка TLS-сертификата обязательна;
не использовать insecure/skip-verify. Параметры WebSocket и авторизации брать
из выбранной записи защищённой подписки. URL подписки, её токен и ключи
не включать в документацию, Git или журналы. Фактическая конфигурация хранится
в `/etc/loginom-swarm-vpn` с закрытыми правами.

Ожидаемый выходной IP по-прежнему `185.21.15.251`. Совпадение с адресом endpoint
не заменяет независимую проверку выхода из хоста, sandbox и контейнеров.

- Host TUN: `auto_route`, `auto_redirect`, `strict_route`, начальный MTU 1400.
  Выделить непересекающиеся подсети; Docker bridge — `br-swarm`, `172.28.0.1/24`
  после проверки отсутствия конфликтов. Весь внешний трафик хоста, контейнеров,
  worker, CLI и Chromium проходит через VPN.
- Сохранить необходимые прямые LAN-маршруты, включая `10.200.0.0/16` и
  `10.150.0.0/22`. Удалить безусловный обход для всех SSH и всего
  `kartamyshev.dev`. Внешний DNS — через VPN; `bg.local` и `basegroup.ru` — через
  внутренние DNS. Публичного прямого fallback быть не должно.
- DNS Docker получает через доступный адрес bridge, не через хостовый loopback.
  Сохранить системный resolver и внутреннее разрешение имён контейнеров.
- Docker оставить на iptables через iptables-nft. Независимая постоянная защита
  OUTPUT/FORWARD загружается до контейнеров и моделей. Не очищать общий ruleset
  и таблицы Docker/sing-box. Прямой внешний выход разрешён только VPN-процессу
  к точному endpoint; необходимый LAN, DHCP и внутренний DNS сохраняются.
- Учесть TCP, перенаправленный с выделенного bridge в INPUT listener sing-box;
  listener не открывать всей LAN. Прямой публичный IPv6 блокировать. Общее
  исходящее разрешение established не должно сохранять прямой канал без TUN.
- Проверить время перед OAuth. До активации профилей и перед каждым модельным
  этапом проверять фактический выходной IP `185.21.15.251`.
- Проверить stop, kill, недоступность endpoint, reboot и Docker restart: прямой
  fallback, DNS- и IPv6-утечки запрещены; LAN SSH и интерфейс остаются доступны.
  Сохранить прежнюю сеть и автоматический возврат административного доступа
  при неудаче; такой возврат оставляет модельные процессы остановленными.

## Состав снимка, права и авторизации

Обычная копия недостаточна: она не содержит часть инструментов и настроек,
а текущий backup может сам запустить остановленный Paperclip. Создать отдельный
полный снимок без автоматического запуска служб.

Включить:

- Логический PostgreSQL 17 dump, необходимые роли и права, расширения,
  fingerprint данных. Живой каталог PostgreSQL не использовать для восстановления.
- Compose, настройки, секреты и ключи Paperclip, instance identity, uploads,
  файловое хранилище; прежние Caddy config/state сохранить для отката.
- Полные worker profiles, независимые checkout с `.git`, рабочие ветки, состояние,
  установленный CLI и symlinks; фактические runtime, toolchains и manifest.
- `/etc/loginom-swarm`, настройки memory gateway, регистрации, доверенные hooks,
  реальные thread ID, capture cursors и journal; recovery CLI и доказательства.
- Серверный профиль личного GitHub CLI, identity; systemd units/drop-ins, AppArmor,
  необходимые настройки ядра и сведения о пользователях; семь дней старых копий.

Не переносить `/run`, PID-файлы и живые сокеты. Проверять hashes, modes, owners
и symlinks. Передавать потоком через два SSH-соединения и Mac, без полного архива
на его почти заполненном диске. На назначении использовать закрытый staging,
проверить hash перед распаковкой с sudo.

Администратор `user` уже имеет UID 1000. После проверки свободных номеров создать
worker UID/GID 21001, publisher 21002, memory 21003 и VPN 21004. Переназначать
владельцев только по manifest; root-owned код остаётся root-owned. Не применять
массовый chown ко всему runtime. Unix sockets остаются закрытыми; проверить
SO_PEERCRED и отказ посторонним UID. Будущая контейнерная интеграция должна
учитывать новый UID без ослабления прав сокета.

Серверные OAuth-профили переносить из остановленного снимка; токены с Mac
не копировать. Повторный OAuth нужен только при подтверждённой недействительности.
Публикация — от `kartamyshev-dev` через отдельного публикатора, без токена у моделей.
Центральный `ov.kartamyshev.dev` не переносится; канонический Peer неизменен:
`viking://user/kartamyshev/peers/-Users-kartamyshev-Git-loginom-ai-agent/memories`.
Не выводить новый Peer из серверного пути и не выполнять повторный enrollment
поверх действующих регистраций. Сохранить `loginom-account.json` и шесть recovery-записей.

## Репетиция, остановка источника и восстановление

1. Подготовить назначение, VPN, закрытые каталоги и пользователей. Перенести
   неизменяемые инструменты и закреплённые образы.
2. Выполнить пробное восстановление изолированно, без внешних соединений,
   обновления OAuth, capture и запросов моделей под копиями идентичностей.
   Проверить hashes, права и совместимость runtime с Ubuntu 26.04.
3. Закрыть запись через старый интерфейс и остановить backup timer. Проверить
   отсутствие заданий, получить общую блокировку тяжёлых операций; блокировки
   по возрасту не удалять. Остановить app, worker, memory и publisher.
4. Сделать свежий dump и файловый снимок с последней блокировкой CLI. Зафиксировать
   состояние служб. Исключить автоматический запуск источника после reboot.
5. Восстановить чистую БД на прежнем digest, останавливаясь при ошибке; затем файлы
   и точное сопоставление владельцев. Проверить manifest. Не обновлять схему,
   Paperclip или образ форка одновременно с переносом.
6. Caddy обслуживает HTTP на порту 80, без ACME и принудительного HTTPS; доступ
   ограничен LAN, app и DB не опубликованы. Настроить authenticated/private,
   явные public/auth URL `http://loginom-swarm.bg.local`, разрешённый hostname.
7. API-клиент получает explicit `PAPERCLIP_BASE_URL`; при отсутствии сохраняется
   старый HTTPS + DOMAIN. Существующие users/company/project/case IDs и ключи
   сохраняются. Повторный onboarding и создание владельца не выполняются.
8. Прежнюю Cloud identity сохранить как неиспользуемую pipeline-связь. Не обходить
   запрет HTTP reenrollment. Рабочая публикация остаётся через личный GitHub CLI.
9. Активировать только одну копию после VPN gate: `processingEnabled=false`,
   Sampling в setup, роли без автоматических запусков. Worker: `MemoryHigh=20G`,
   `MemoryMax=24G`; один тяжёлый этап, сборки под тем же ограничением.

## Приёмка и резервное копирование

Подтвердить расширение ext4 и минимум 20 ГБ свободного места, DNS после DHCP/reboot,
HTTP порт 80 с Mac, вход прежнего владельца, отказ анонимному API и сохранение
origin/CSRF-защиты. Сверить IDs, количество объектов, fingerprint БД и hashes.

Проверить VPN из хоста, реального sandbox worker, контейнера и Chromium; проверить
отказы и утечки по физическому интерфейсу. Подтвердить отсутствие доступа моделей
к секретам Paperclip, чужим профилям, GitHub-токену и Docker socket. Chromium
работает непривилегированно, со штатным sandbox, без `--no-sandbox`.

После замораживания источника проверить OAuth и короткие запросы согласованных
моделей без запуска узла; memory read/capture/readback с сохранением Peer/threads/
cursors и запретом чужого Peer. Проверить GitHub identity и право push без нового
PR ради миграционного теста. Перезагрузка сохраняет профили, VPN-защиту и закрытые
допуски. Не повторять CSV upload, Loginom-приёмку, cleanup или снятие recovery.
Модельные инфраструктурные проверки проходят без инструментов Loginom.

Исправить daily backup: возвращать только службы, работавшие до копирования.
Полный миграционный снимок ничего не запускает. Расширить покрытие на настройки
VPN/Swarm, инструменты, профили, ветки, память и recovery. Проверять восстановление
по manifest, независимо от живого источника. После успешного отдельного restore
включить timer только на новом сервере; хранить семь дней. Копии на этой же ВМ
не защищают от её полной потери.

Проверить скрипты при повторном запуске, прерванной передаче, неверном hash,
ошибочном выборе сервера, ошибке restore и остановленных до backup службах.
Изменения upstream-файлов включить в реестр, выполнить применимые проверки
репозитория; существующие незакрытые проверки явно перечислить.

## Откат и передача

До новых записей остановить назначение и вернуть исходные URL/службы источника.
После OAuth refresh, записи в БД или capture сначала получить согласованный
обратный снимок назначения и восстановить источник. Устаревшие профили и cursors
не запускать. Неизвестная внешняя мутация остаётся blocked. Одновременно работает
только одна копия, способная писать во внешние сервисы, память и БД.

Обновить активные локальные реквизиты после успешного переключения, сохранив
доступ к источнику отдельно. Передать manifest версий и образов, отчёт PASS/FAIL/
BLOCKED, инструкции SSH/VPN/OAuth, backup/restore/rollback, описание DHCP/DNS
и список оставшихся задач. Фактические действия и доказательства записывать
в `doc/loginom-swarm/MIGRATION-2026-09-25.md`, обновить checkpoint и оформить PR.

Итог: перенос может получить PASS только после проверок данных, прав, авторизации,
сети, sandbox, reboot и restore. Sampling не обрабатывался; CLI gate остаётся
BLOCKED. Полный Swarm готовым не объявлять.
