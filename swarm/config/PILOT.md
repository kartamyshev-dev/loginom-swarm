## Предмет работы

Два детерминированных режима из реестра: «Последовательный» и «Отбор со смещением». Не включать случайный и стратифицированный отбор. До разработки подтвердить семантику обоих режимов по Loginom Help и живому UI и создать предметный подплан. Числа и смысл параметров не угадывать.

Один worktree/ветка `sampling-pilot`. Разработчик и ревью — Astra medium, отдельная автономная приёмка — standalone Loginom AI Agent CLI, Sol low через ChatGPT OAuth. После разработки одно ревью в той же сессии, затем адресные исправления. Приёмка получает только бизнес-ТЗ и входные данные; независимые ожидаемые результаты и аудитор остаются вне её контекста. Проверять сохранение и независимое повторное открытие пакета.

PASS означает подтверждённую реализацию и приёмку заданных режимов, а не слияние, публикацию или начало следующего узла. Интеграция, push и релиз отдельно не разрешены. При исчерпании авторизации, отсутствии памяти, неизвестном результате мутации либо невозможности cleanup сохранять точный checkpoint; не перезапускать слепо и не выдавать PASS.

## Серверная архитектура

Paperclip хранит задачу, назначение, документы и отчёт. Исполнение идёт от отдельного пользователя `loginom-worker`, без sudo и доступа к Docker socket. Рабочие файлы располагаются под `/opt/loginom-worker`; SSH-реквизиты администратора туда не копируются.

Разработка и приёмка идут последовательно, без одновременной сборки и браузерной приёмки. Linux браузер работает под Xvfb от непривилегированного пользователя с включённым Chromium sandbox. На сервере 3 CPU, 3.8 GiB RAM; до старта исходно доступно около 2.3 GiB. Это предварительная оценка, не результат нагрузочной проверки.

Серверная адаптация памяти обязательна: штатный регламент регистрации worktree привязан к Codex task/turn ID и доверенным hooks. Наличие файлов не подтверждает работающий admission. Проверить совместимость серверного Codex и capture, не подменять receipts и не подставлять вручную чужой Peer.

## Начальные условия запуска

1. Проверить Linux runtime, сборку, Chromium sandbox и запас памяти.
2. Выполнить отдельный штатный вход ChatGPT для разработчика и CLI-приёмки; проверить точные модели. Не переносить авторизацию Mac без явного решения.
3. Настроить выделенное подключение Loginom, проверить отсутствие конкурирующей работы на аккаунте.
4. Подготовить и проверить общую память нового worktree.
5. Создать проект/задачу и исполнителя через API Paperclip. Задача — backlog, агент — paused, таймер выключен.
6. После проверки admission пользователь вручную разрешает запуск в Paperclip. Настройка через API не должна запускать heartbeat, probe модели или исполнение задачи. После результата не выбирать следующий узел.

`pilot.json` — спецификация и начальное состояние, а не работающий планировщик. Серверное состояние кампании хранить приватно отдельно от Git. Реальная готовность и оставшиеся блокеры отражаются в `CHECKPOINT.md`.
